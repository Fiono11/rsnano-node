# RAI pause/report/resume experiment

Implements the requested epoch boundary: once epoch e's deadline has elapsed and e-1 is closed, pause new epoch-e signing and capture the pending active election roots under the signing-state lock. Start epoch e+1 voting immediately. Existing epoch-e statements remain replayable and incoming old votes remain applicable.

Each weighted committee member signs an immutable report, including an empty report when it has no pending elections. Reports carry qualified election roots and candidate hashes for ordinary vote/block recovery. Paged reports bind their epoch, full-report digest, page number, page count and page contents in the signature. They cannot enter close-vote tallies. Pages are reassembled and checked against the full-report digest before counting the reporter. Replays count once per representative and root.

Every committee report is required. The cut includes roots reported by weight strictly greater than floor(19% of total committee weight), matching RAI's configured f and the requested f+1 threshold. Only cut roots resume new epoch-e statements. Non-cut roots remain able to process/replay old votes, but cannot generate new FIRST, NOTARIZE, TIMEOUT or FINAL statements. Existing cross-epoch signing and final-vote locks remain in effect.

Cut roots must terminate locally (notarization, finalization, or timeout, including retained block-tree outcomes) before this PR starts signing close proposals or persists a recovered close decision. Pending cut roots receive bounded rotating ordinary ConfirmReq recovery. Reports are retransmitted and local reports survive close advancement in the existing archive so lagging PRs can collect them.

Candidate membership continues to come from notarized and finalized blocks, dependencies and prior canonical membership. Later rounds can propose updated membership; an existing signed candidate is never edited. The decided digest remains immutable. Epoch e+1 cementation is permitted while e closes, with the voting epoch as the application bound.

This deliberately retains the user-requested all-reports barrier. An absent committee member prevents progress. It is an experimental wire-format change (EpochClose kind 8), and a successful six-node workload is not a Byzantine safety or liveness proof. Conflicting signed reports are not reconciled by a separate cut-agreement protocol; each receiver retains the first admitted report commitment for that sender.

Nanospam now accepts `--closed-epochs 2`, passes a benchmark-only close cap to its nodes, and verifies exactly two matching closed epochs. The normal node epoch schedule is unchanged when the nanospam start-file environment is absent. Benchmark runner: `target/nanospam-cut-20260910/run.py`. Successful-run data is removed only after nanospam exits; failure data is preserved.

Validation before benchmark: 666 node unit tests, 169 ledger unit tests, 82 message unit tests passed with RAI enabled; 35 nanospam tests passed and one was ignored. Feature-disabled node check passed. Tests cover report authentication, page reordering, duplicate counting, all-report requirement, f+1 boundary, pause restrictions, non-cut restrictions, and immediate next-epoch signing.

## Benchmark result: PASS

`b51260-r1026-cut-02` passed in **151.909 seconds** including setup and teardown. Six fresh PRs, 51,260 blocks, 51,260 accounts, requested rate 1,026 blocks/s, 5% forks, `--no-prio`, 40-second epochs, exactly two verified closed epochs. All blocks were published. No compilation overlapped the run. No panic was logged, no benchmark/node processes remain, and successful node data was deleted. Nanospam uses its existing child kill/wait teardown.

All six PRs derived the same 91-root cut for epoch 0 and an empty cut for epoch 1. Epoch-0 local drains completed 49.193–51.735 seconds after the shared anchor; epoch-1 local drains completed 81.714–82.903 seconds after the anchor. Close rounds were 1–2 for epoch 0 and 0–1 for epoch 1. One PR reconstructed the epoch-1 decision but temporarily lacked membership validation; ordinary recovery eventually made it valid without code changes or a relaxed deadline. The precise missing evidence was not captured before it recovered.

## Frozen-election scheduling correction

The original pause stopped new statements at signing authorization, but periodic AEC voting still scheduled paused and non-cut roots. Those targets could consume generator work or replay old statements while fresh epoch-1 work competed for the same resources.

The periodic target filter now checks whether the election's epoch/root is active for voting before allowing either normal or final targets into the scheduler output. Accelerated second-look notifications use the same predicate. During report collection, all epoch-e roots are excluded from these paths; after collection only the cut resumes. Fresh epoch-e+1 roots remain eligible. Explicit request/recovery authorization and incoming old-vote processing are unchanged. Work already queued at the instant of pausing can still reach the existing signing guard; the correction prevents repeated enqueueing through these two paths.

The deterministic regression checks paused versus resumed scheduling for cut, frozen and fresh roots, both normal and final targets, and verifies an excluded root's old FIRST remains recoverable while a new FINAL is forbidden. All 667 RAI node unit tests passed; the feature-disabled node check and release build passed. This change does not alter snapshot computation, transport, vote thresholds or epoch deadlines.

### Scheduling-correction benchmark: convergence PASS, latency unresolved

`b51260-r1026-frozen-scheduler-01` passed the unchanged six-PR workload and exactly-two-epoch verification in **104.819 seconds**, versus 151.909 seconds previously. All 51,260 blocks were published. No compilation overlapped the run. Successful node data was deleted after nanospam exited.

The lower wall time does not demonstrate improved election latency: epoch-1 nonfork finalization mean/p95 increased from 3,102/6,235 ms to **7,894/11,333 ms**. The randomized runs had different boundary cuts (156 roots now, 91 previously) and close rounds (epoch 0 now 2–4); this single comparison cannot attribute the regression to one cause. The scheduling inefficiency is corrected, but it was not established as the dominant cause of the epoch-1 slowdown.
